Here we will introduce some bugs to test the architecture. The complete outputs can be retrieved in the appendix and will be linked promptly. [cite: 167, 168]

\section{Bug 0}
We used the \texttt{DONE} state instead of \texttt{IDLE} after a failing packet.

\begin{description}
    \item[Original:] \lstinline[style=svlog]|state <= IDLE;|
    \item[Bugged:]   \lstinline[style=svlog]|state <= DONE;|
\end{description}

The trace can be reviewed in the appendix \ref{out:bug_0}.

\subsection*{Analysis}
The tool \textbf{REFUTE} the \texttt{checksum\_idle} property.
A single counter-example is given and it shows the trace that leads to a failure of the assertion. 
At state 10 the FSM is in the state \texttt{CHECKSUM} (011) with \texttt{chk\_fail} asserted, but instead of returning to \texttt{IDLE} (000), the bug forces the FSM to become \texttt{DONE} (100).

\section{Bug 1}
Here we changed the \texttt{abort} state into a non-existent one: \texttt{3'd5}.

\begin{description}
    \item[Original:] \lstinline[style=svlog]|state <= IDLE;|
    \item[Bugged:]   \lstinline[style=svlog]|state <= 3'd5;|
\end{description}

The trace can be reviewed in the appendix \ref{out:bug_1}.

\subsection*{Analysis}
The tool \textbf{REFUTE} two separate properties simultaneously: \texttt{\_abort} and \texttt{\_state}.
Two distinct counterexample traces were generated, one for each property, but they both look at the same bug from different perspectives.
In state 9 the FSM is in the unknown state (101), this is a violation of both properties.
On one hand, the inputs that led the dut to the violation, should have returned a \texttt{DONE} state. 
On the other hand, that state does not even exist.
